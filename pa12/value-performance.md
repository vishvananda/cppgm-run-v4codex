## Results

Common outputs remain byte-identical. In the final campaign, median paired
compiler time for 1000 classes is A/C 0.24857/0.24985 seconds; peak timed RSS
27276/27568 KiB. At 4000 classes these are 1.07187/1.06597 seconds and
95568/96860 KiB. Paired C/A ratios are 0.997/1.038 and 0.995/0.980.
Native text remains 70053/280053 bytes. These tiny generated programs are
startup-dominated; their runtime observations establish no speedup. The
checked volatile empty-destructor loop runs 0.15444/0.15436 seconds, with
241 bytes of native text on both sides (paired ratios 0.992/1.025).

Review found repeated preparation of nested conditional branch conversions.

Paired compiler ratios are 0.240/0.224 and 0.064/0.066. The replacement adds
64 bytes of compiler text and changes no generated bytes. Runtime ratios
0.908–1.049 across the four paired blocks are measurement variation, not a
runtime benefit. Fourfold nesting now produces 3.977x conversion objects;
the previously quadratic preparation was removed. The final timing ratio
across depths is 5.18, so the work counters, not timing alone, support the
representation's work bound.

New direct/indirect value workloads at 1000/4000 classes take median
1.11022/2.16929 seconds and peak timed RSS 97884/366192 KiB. They emit
388053/1552053 native bytes. Return records are exactly 3000/12000 and
conversion-object records exactly 7000/28000. The checked two-million-

All samples, including variable latency, remain in `value-performance.json`.
Compiler ranges are 0.96369–1.34911 and 2.12960–5.66230 seconds; the loop
runtime range is 0.06183–0.06573 seconds. No timing-based linearity claim is made.
The complete stage additions grow compiler text by 18240 bytes (2.24%) from
A. These are measured semantic/ABI costs, not an optional optimization claim.

## Work budgets and validation

Class ABI facts are prepared once per complete class; declarations, selected
transfers and source return records have compact identities. The existing
member demand queue remains the only helper-body owner. A conditional reuses
its two recorded value conversions; glvalue return arms receive two contextual
transfer records. Relocating an operator operand slice is bounded by its three
operands. There is no body cloning or repeated conditional-subtree preparation.

The cleanup-presence query memoizes each parsed node, including negative
results. A branch merge adds at most one persistent cleanup state pointing
to the two selected suffixes and their common tail; it does not copy suffix
lists. Each required cleanup state/terminal pair is emitted once. This bounds
stored branch facts by branch count and object states by materializations.
Existing transfer array expansion stays capped at eight elements. No new
speculative work, generated-code-growth allowance or backend gate is added.
