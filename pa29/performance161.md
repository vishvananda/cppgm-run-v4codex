# PA29 implementation161 performance evidence

Code: `802f28fd`; entry: `7f0a2c4b`. Required O0 atomic capability, with
no optional optimization and no speedup claim. [Ownership and complexity](implementation161.md)
explain the work. The [manifest](../student.tests/pa29/evidence161/manifest.json)
records frozen compiler/input/script hashes, flags, platform and raw observations.

## Protocol and equivalent correct workloads

A/B binaries were frozen before timing. CPU affinity is 0; compiler and checked
executable wall time are measured separately, with `/usr/bin/time` peak RSS.
No build or test process overlaps timing; host scheduling remains uncontrolled.
The compiler uses `-O0 -c --stats`, built with `-std=gnu++11 -Wall -O3`.
Host g++ only links the benchmark objects produced by this compiler.

[Common observations](../student.tests/pa29/evidence161/common-performance.json)
retain 224 measurements: four A/A samples and six ABBA blocks per compilation
and runtime workload. Fixed inputs contain 2400 demanded template functions,
loops, calls, memory, floating point and exceptions. Runtime argc and checked
results prevent measuring dead work. The pruning case adds 1200 unused functions.
[Atomic observations](../student.tests/pa29/evidence161/affected-performance.json)
add 56 equivalent measurements of 1200 GNU add specializations and six million
checked atomic calls, using the same A/A and ABBA protocol. All five A/B object
and executable pairs are byte-identical; common semantic/native work counts agree.

## New atomic capability costs

A rejects the C11 inputs; failure latency is not a correct equivalent baseline.
Each size has eight compilation and eight checked execution observations. Every
specialization contributes to a result check. Six million calls read runtime argc,
initialize atomic storage, perform CAS-based XOR and atomically load the result.
The generator checks the final sum independently. A preliminary harness invocation
failed before collecting samples due to a Python argument-name collision; it was
fixed before the retained measurements, with unchanged compiler binaries.

Measured latency is affected by the recorded timing variation; no sublinear-time
claim follows from the largest sample's lower median.

## Stage acceptance and budgets

No optional transform was added: its work and growth budgets remain **zero**.
Compiler binary size changes from 3962664 to 4005656 bytes (+42992); all five equivalent
generated text sizes are unchanged. New-capability text grows with required
functions and operations. Existing constexpr depth/step limits, native alignment/frame
limits and course timeouts are unchanged. Conservative sequential consistency
and strong compare-exchange satisfy the required contract; tuning weaker orders
would need separate legality/profitability evidence.

Necessary atomic semantic/storage work is accepted at PA29; there is no optional
optimization benefit being used to justify compiler work. Historical blanket
15% latency/RSS and zero-growth targets remain diagnostic under spec §9. All prior
measurements are preserved; mandated limits, correctness and coverage are intact.
PA30–34 retain broad hosted runtime, optimization/allocation and self-hosting
ownership. This accepts the atomic group only: PA29 remains at 338/403.
