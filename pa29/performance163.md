# PA29 implementation163 performance evidence

Code tip: `a6f3d6a2`. PA29/O0 required-capability acceptance; no optional optimization or speedup claim.

The [manifest](../student.tests/pa29/evidence163/performance-manifest.json) freezes entry/final binaries, scripts, flags, CPU and inputs. Compilation and checked execution are measured separately with CPU affinity 0, wall clocks and `/usr/bin/time` peak RSS. No compiler build or correctness suite overlapped measurement; light documentation/evidence inspection and external scheduling were uncontrolled. All observations, including outliers, remain.

Common correct workloads retain four A/A calibration samples and six ABBA blocks per mode/workload: **224 observations**. Affected demand shapes have eight samples per mode: **96 final observations**, plus six launcher calibrations. An earlier two-million-iteration experiment was lengthened to twenty million so runtime dominates launch overhead; its **96 observations and six calibrations** are [preserved](../student.tests/pa29/evidence163/affected-preliminary-performance.json).

[Final affected observations](../student.tests/pa29/evidence163/affected-performance.json) measure final capability and scaling only. Register recipes add a runtime value and swap its bytes twice. That variation does not establish a speedup. Only one source assembly recipe is parsed, with no compiler retry loop or source replay.

## Acceptance and limits

Compiler binary size grows from 4,009,912 to 4,048,384 bytes (+38,472). Equivalent common generated text is unchanged. Required new lowering has explicit linear bounds in [assembly163](assembly163.md); additive updates reuse the direct atomic primitive. Other supported locked updates use a fixed-size CAS loop and are validated separately for behavior. Their compiler work is bounded; runtime contention is not compiler search.

No optional transform is added: new optional work and growth budgets are **zero**. Existing constexpr step/depth bounds, native frame/data/alignment bounds and assignment timeouts remain. Historical blanket 15% latency/RSS and zero-growth targets are diagnostic, as previously classified under spec §9; all old and preliminary evidence is preserved. No PA29 correctness requirement or coverage is reduced. Broader hosted runtime, optimizer/allocation and self-hosting costs remain with PA30–34.
